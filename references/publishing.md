# 发布规范（小红书）

## 图片

- 尺寸 **1080×1440（3:4）**，PNG 或 JPEG，单张控制在 1 MB 内。
- 一次 8–12 张，文件名按 `01-XXX.png` 排序，上传顺序即文件名顺序。
- 封面（第一张）承担点击率：一句话结论 + 一张有质感的图。

## 文案：必须是纯文本

小红书正文**不解析 markdown**。`**加粗**`、`> 引用`、`- 列表` 都会原样显示成符号。

- 交付时用代码块包住可复制的标题与正文，并注明"直接复制"。
- 层次靠换行、空行和小节符号（`▍`、`—`）做，不靠 md 语法。
- 标题 ≤ 20 字，三个备选；正文含标点 ≤ 1000 字。
- 话题标签放正文末尾或发布时的标签栏。
- 正文字数够用时不要删信息，但也别为了凑字数重复正文里的句子。

## 合集

- 先判断笔记的**内容属性**再选合集，不要往"最接近的大筐"里塞。
- 与已有合集都不是一类时，新建一个。命名留出继续做的余地
  （「品牌视觉拆解」优于「美学拆解」，前者能容纳后续几期）。
- 合集定位被稀释的代价是以后自己也找不到。

## 发布后要改图

**先分清两个问题：改动会不会被处罚 ≠ 改动会不会有代价。**
平台不处罚"编辑"这个动作（互动数据、原发布时间都保留，这不是违规），
但**每次编辑都会让系统重读一遍内容、重新决定推给谁**，审核期间分发受影响。
用户口中的"改完就掉"，掉的是后半句，不是前半句。
拿前半句的结论去回答后半句的问题，是本 skill 首期犯过的错。

### 风险由「改什么」决定，不由「改几次」决定

| 档 | 典型改动 | 会发生什么 |
| --- | --- | --- |
| 低 | 错别字、标点、补一句解释 | 语义指纹不变，基本无感 |
| 中 | 换封面、换标题、改话题标签 | 系统重新理解内容，可能换一批推荐人群 |
| 高 | **换整组图**、正文重写、主题转向 | 用旧壳装新内容，等于重新排队 |

**换整组图属于高风险档，不是"只是换了几张图"** —— 一条笔记的图片是系统判断
"该推给谁"的主要依据之一，整组替换等于把判断依据全部换掉。

**整组图里最不该动的是第一张。** 封面是单点权重最高的元素：点击率是所有推荐的第一道门，
笔记能不能进入下一层流量池由它决定。笔记发布后，封面会积累一批"已验证对它有点击意愿"的人群画像；
换掉封面等于把这份优势清零、重新开一次点击率测试。
**所以：封面必须一次定死；确实要换，也是单独一次、且必须在笔记还没起量时。**

### 判据：看笔记走到哪一步，不看你想改什么

| 阶段 | 动作 |
| --- | --- |
| 曝光很少、没人互动 | 可以改一次，这是成本最低的窗口 |
| **互动在涨（有赞、有收藏）** | **一律不动**。正在爬说明分发正在进行，动它等于把已知结果换成未知数 |
| 已跑成爆文 | 只改错别字；标题、封面一律别碰 |
| 有硬伤（价格、时间写错） | 立刻改，流量的事往后排 |

判断"在不在爬"看**互动有没有变化**，不是看发布了几分钟。
"发布不到一小时"不等于"没代价"——冷启动恰恰发生在这段时间里。

### 硬约束

- **发布当天不出现第二次编辑。** 一次是上限，不是目标。
- 第三方口径「每日最多 3 次」「最多 5 次」互相矛盾且无官方原文，
  **不要把任何数字当额度去用**。
- 编辑界面标题栏的 `N/18` 是**图片张数**上限，不是编辑次数上限。
- 换图时**点图片本身**替换，不要碰 `+`——它不是"超限才报错"，
  而是真的会插进一张，图序后移、首图可能换人。
  平台给每张图打角标序号，序号 = 最终顺序，**换完照着角标回归位**最快。
- 保存后重新过审，几分钟到数小时刷不出新图是正常的。
  **改完 2 小时就看数据等于看噪声**，给 24–48 小时观察窗。

### 交付纪律（由此反过来）

**图必须在发布前定死。** 出图、逐页读图、字号核对全部完成后再交给用户发布；
交付时明确说一句「发之前确认，发之后不改」。

真需要大改时，三个动作的取舍：

| 动作 | 代价 |
| --- | --- |
| 编辑 | 重审 + 重新找人；换整组图等同重新排队 |
| 删除重发 | 互动清零、丢掉正式发布时间、短期重发高相似内容有判重风险 |
| **另发一篇不同角度的** | 不动原笔记，新笔记有独立冷启动窗口 |

所以大改的正确答案是**第三个**：不是编辑，也不是重发同一份。

### 「重新发」不是一个动作，是三个，三本账

| 动作 | 账 |
| --- | --- |
| **删掉再发同一份** | 最差。查重看的是**图片指纹 + 内容语义**，不是时间间隔；重发拿不到首发级试投（第三方实测：初始曝光约为正常新笔记的六成） |
| **不删旧的、再发一份相似的** | 次差。站内同时存在两份高度相似的内容，系统不需要任何推理就能认出来；关注者还会在信息流里看到两张一样的封面 |
| **改一改再发** | 不可控。「改到多少算新内容」没有公开阈值，你以为改了 30%，系统可能仍判为同一条 |

**「隔几天再发就没事」是错的**：系统数的是**重复度**，不是间隔天数。
三天前发过和三个月前发过，对读者是同一件事——他见过了。

删掉一篇的确定损失（各方说法都不否认）：**历史互动、已积累的搜索位置、以及唯一的诊断数据**。
小红书搜索属性强，有些笔记的浏览量本来就靠搜索慢慢长出来，曲线平而长；
删掉等于把还没开始的长尾一起删了。**想降低可见性就用「仅自己可见」，不要删。**
（「删除会不会影响账号权重」**没有官方口径**，社区两派说法互相矛盾且都很绝对——
别拿它当决策依据，只拿上面那三样确定损失做判断。）

### 修正的正确答案常常是「下一篇」，不是「这一篇」

已发布的内容有瑕疵 ≠ 必须修。**它只要还在跑，就比一个未知数值钱。**
把修正放进下一篇：那篇有干净的冷启动窗口，而这一篇不用再挨一次重审。
首期实测的代价：第一版已在跑（有赞有收藏），却因为"排版不够好"连修三轮，
失去了它原本的曲线——而这套排版本该直接用在第二篇上。

### 发布后想补一把，只有评论区能动

图片和正文之外，唯一不触发重审的入口是评论区：

- **先回复已有的每一条评论**（楼中楼）。第三方口径的新版 CES 权重是
  赞 1 / 藏 1 / **评 4** / 转 4 / 关注 8 —— **一条评论的分值是点赞的四倍**，
  回复评论还会把已经互动过的人再拉回这条笔记里，性价比高于任何其他手段。
- 再发一条**置顶补充评论**：一个笔记里没展开的点 + 一个具体、容易回答的问题。
  **提问比求赞有效**，回答成本越低越好（选择题式提问优于开放式）。
- **让读者之间聊起来**（楼中楼）。第三方口径：评论区出现用户之间的经验交流、专业讨论时，
  系统可能额外给一次推荐；而「求教程」「怎么买」「私信我」这类纯导流评论会降低推荐优先级。
  所以引导方向是"能争论/能互补的具体问题"，不是"求支持"。
- **不要**在评论里写"改了图""帮我看看""求支持"：一是等于主动向系统标注这条笔记动过，
  二是观感差，诱导互动本身也在风控范围内。
- **期望值放这里**：评论区提高的是**重新进池之后的表现**，**不是**把笔记从冷启动池里拉出来。
  它救不了被打断的冷启动窗口，只能让下一次分发测试时数据好看一点。

由此改交付文案：正文或末页**留一个可回答的具体问题**，把评论入口提前铺好，
不要等到发布后再去补。

## 素材与署名

- 引用他人的作品（广告片、设计、截图）时在末页标注来源与是否加工，
  并说明非商业用途。不要只写"侵删"。
- 转述数据、色值、参数这类信息时注明出处与查阅日期。
